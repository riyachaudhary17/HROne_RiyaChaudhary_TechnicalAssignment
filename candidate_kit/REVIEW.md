# Starter code review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses the punch timestamp's timezone/date directly, can mis-handle overnight shifts, and has no explicit whole-second truncation. | Test an IST boundary, an overnight shift, or a punch at 09:40:00.900. | Normalize instants to UTC seconds, derive the IST attendance date, and compare with that date's IST shift start. |
| 2 | `compute_work_hours` | Python `round` uses ties-to-even, while the contract requires decimal half-up rounding. | A duration exactly halfway between hundredths can round to the even hundredth. | Use `Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | Always uses the attendance date, so overnight shifts use the wrong shift-end instant; it also counts any positive overtime instead of requiring 30 minutes. | Punch out after midnight on an overnight shift, or 29 minutes after shift end. | Move overnight shift-end to the next day and apply the 30-minute threshold before flooring minutes. |
| 4 | `EmployeeIn`, `PunchInIn` | Missing contract validation for employee codes, email, lengths, dates, shift format/equality, allowed presence statuses, and epoch-millisecond type/range. | Submit malformed fields, seconds, a float timestamp, or an invalid status. | Replaced with validated Pydantic request models. |
| 5 | `health` | Always returns ready without checking MongoDB. | Stop MongoDB and call `/health`; the starter still returns 200. | Ping MongoDB and return 503 when it is unavailable. |
| 6 | `create_employee` | Check-then-insert is racy without a unique database index; `created_at` is naive and is not converted to epoch milliseconds in the response. | Send concurrent creates for one code, then inspect response timestamps. | Enforce a unique `emp_code` index, handle duplicate-key errors as 409, and use UTC BSON dates/API epoch milliseconds. |
| 7 | `list_employees` | Skips the first page, counts unfiltered employees, does not sort, and does not enforce pagination bounds. | Request page 1 with a department filter and compare total/order. | Apply the filtered count, `emp_code` sort, correct offset, and page constraints. |
| 8 | `punch_in` | Missing employees cause an unhandled access error; timestamp conversion uses local time and treats `0` as omitted; it does not apply IST/overnight date rules or second truncation. It also has no unique attendance-key enforcement and returns MongoDB's internal ID. | Punch for an unknown employee, pass a boundary timestamp, or race two same-day requests. | Validate the employee, normalize epoch milliseconds, derive the R1 date, use a unique (`emp_code`, `date`) index, return 404/409, and omit `_id`. |
| 9 | `list_attendance` | Loads the entire collection into memory, sorts incompletely, slices pages without validating them, counts after fetching rather than applying database filters, and exposes internal IDs. | Exercise it with a large collection, tied dates, filters, or page 0. | Filter/count/sort/page in MongoDB with stable contract ordering and serialize only API fields. |
| 10 | `app/main.py` | Punch-out, correction/audit, analytics, and explain operations are absent. | Call any of the remaining contract paths. | Implemented all missing endpoints, atomic updates, aggregation pipelines, and indexed explain operations. |

**Not defects:** `date` and `joined_on` being strings and shift times being `HH:MM` strings are intentional data-model choices, not timestamps. Using `emp_code` rather than MongoDB `_id` as the external key is also required. Authentication and authorization are outside this assignment's contract.
